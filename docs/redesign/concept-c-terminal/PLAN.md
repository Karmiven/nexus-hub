# План реализации — Концепт C «Терминал» (по референсу владельца)

> **Эталон**: `demo.html` в этой папке — открой и изучи разметку/CSS. Концепт сделан по скриншотам-референсам владельца — визуал воспроизводить максимально точно.
> **Обязательно**: прочитай `docs/redesign/README.md` (общие сведения + «Инварианты»).

## Идея

Угольно-чёрный «терминальный» стиль: **янтарный акцент** (#ffb02e), **бегущий тикер** системных метрик под шапкой, **гигантский заголовок NEXUS (заливкой) / HUB (контуром)**, моноширинные метки капсом повсюду, прямые углы (радиусы 0–7px), панели с тонкими рамками. Главная — командный центр: hero → стат-полоса → закреплённая новость + live-список серверов → «Игры в хостинге» → чат + мониторинг узла.

**Фишка вместо/поверх 6 тем — сменные акценты** (`data-accent`): янтарный (default) / бирюзовый `#2ee6c8` / фиолетовый `#a06bff` на одной тёмной базе. ⚠️ Согласовать с владельцем один из вариантов:
- **C-1 (рекомендуется)**: акценты становятся новой системой «тем» — селектор тем в шапке переключает акцент (`localStorage`, как сейчас `theme`). Старые 6 тем удаляются/архивируются.
- **C-2**: акценты добавляются КАК три новые темы в существующий механизм `data-theme` (`terminal-amber`, `terminal-teal`, `terminal-violet`), старые 6 тем остаются. Больше работы на поддержку старых тем в новой вёрстке.

## Дизайн-токены

Из `demo.html` (`:root` + `[data-accent]`):

```css
--bg: #0a0a0c;  --bg-2: #0e0e11;
--panel: #121216;  --panel-2: #17171c;
--line: #222228;   --line-2: #33333c;
--text: #eceaea;   --text-2: #8f8f9a;  --muted: #5c5c66;
--accent: #ffb02e; --accent-text: #17120a; --accent-dim: rgba(255,176,46,.12);
--ok: #3ddc84;     --bad: #ff5c5c;
```

**Шрифты (Google Fonts, CSP уже разрешает)** — заменить текущий URL в `header.ejs`:
- `Unbounded` (700, 900) — заголовки, логотип, крупные цифры;
- `Manrope` (400–700) — основной текст;
- `IBM Plex Mono` (400, 600, 700) — тикер, метки, навигация, адреса, метрики.

Типографические правила: mono-метки — uppercase + `letter-spacing: .1–.18em`, 10–12px; заголовки секций — Unbounded uppercase 22px с линией-«правилом» до края и счётчиком справа (`.sec-head`); контурный текст — `-webkit-text-stroke: 2px var(--line-2)` + `color: transparent`.

## Структура страниц

- **Навбар** (sticky): `⚡ NEXUS`+`HUB`(акцентом), пункты mono-капсом, **активный — в рамке цвета акцента**, справа янтарная кнопка «ВОЙТИ» (или «ВЫЙТИ» POST-формой с `_csrf` для залогиненных).
- **Тикер** (под навбаром, на всех страницах): бесконечная бегущая строка `SYS://NEXUSHUB ● OPERATIONAL · UPTIME · ИГРОКОВ · СЕРВЕРОВ X/Y · NODE · MSK время`. Реализация: трек из ДВУХ одинаковых наборов, `animation: translateX(-50%)`, пауза на hover, отключение при `prefers-reduced-motion` (статичная строка). Данные рендерит сервер; время тикает JS; можно раз в 60с обновлять числа fetch'ем `/api/servers` (опционально, 2-я итерация).
- Навигация — обычные ссылки на маршруты (бесшовность даёт SPA из `main.js`), активный пункт по `res.locals.currentPath`.

| Страница | Маршрут | Изменения бэкенда |
|---|---|---|
| Главная | `/` | ➕ SELECT'ы: серверы (все, для live-списка), закреплённая/последняя новость, 3 сообщения чата, счётчики; `games_list` уже приходит |
| Новости | **новый** `/news` | ➕ маршрут + view `views/news.ejs` (лента переезжает с главной) |
| Серверы | `/servers` | нет |
| Сообщество | `/community` | нет |
| Мониторинг | `/monitoring/dashboard` | нет |

## Фазы

### Фаза 1 — токены, шрифты, примитивы
1. `header.ejs`: заменить Google Fonts URL на Unbounded + Manrope + IBM Plex Mono.
2. `style.css`: токены; примитивы из demo: `.panel`/`.panel-head`, кнопки `.btn-a` (янтарная заливка) / `.btn-o` (контурная), `.st` (статус `● ONLINE/OFFLINE`), `.link-a`, метры `.meter` (трек 4px с рамкой, заливка акцентом, `hot` — красным), `.sec-head` с «правилом».
3. Механизм акцентов: по решению C-1 или C-2 (см. выше). Для C-1: атрибут `data-accent` на `<html>`, применяется до отрисовки (инлайн-скрипт в `<head>` по образцу текущего `theme`), сохраняется в `localStorage`, селектор в навбаре (сохранить/заменить `id="themeSwitcher"` — согласовать с `main.js`).

### Фаза 2 — навбар + тикер + футер
1. `views/partials/header.ejs`: новый навбар (см. `.nav` в demo). Сохранить: `<meta name="csrf-token">`, селектор языка (`id="languageSelector"`, стилизовать под mono-пилюлю), логику показа пунктов (Мониторинг — по `monitoringPublic`/админ, Админ — только админу: пункт `ADMIN` в рамке фиолетового?— нет, акцентом).
2. Тикер `.ticker`: серверный рендер значений (кол-во онлайн из БД — быстрые COUNT'ы уже используются на главной; вынести в middleware с кэшем 30с или передавать только на страницах — решение: лёгкий кэшируемый helper в `config/database.js` по образцу `getCachedSettings`). Часы MSK — `siteTimezone` из locals + JS-обновление раз в секунду.
3. `views/partials/footer.ejs`: однострочный mono-футер: `NEXUSHUB © YYYY · SELF-HOSTED` слева, справа — подпись (настройки `footer_*` из БД сохранить: `footer_copyright` и т.п.).
4. Мобильная: пункты меню — в существующий бургер (`initMobileNav` в `main.js` адаптировать), тикер остаётся.

### Фаза 3 — главная
`views/home.ejs` переверстать по секции `#v-home` demo:
1. **Hero**: eyebrow `// ИГРОВОЙ ХАБ СООБЩЕСТВА V2.0` (текст из `hero_subtitle`? — нет: eyebrow фиксированный i18n-ключ, а `hero_title`/`hero_subtitle` из настроек = заголовок/абзац). Заголовок: первое слово заливкой, второе контуром — рендерить из `hero_title` (сплит по пробелу; если слово одно — только заливка). Кнопки «К СЕРВЕРАМ →» / «СООБЩЕСТВО».
2. **Стат-полоса** `.stats`: 4 ячейки — серверы онлайн `X/Y` (X акцентом), игроки сейчас (сумма `player_count`), аптайм 30 дней (из `server_status_log`: доля online-проверок за 30 дней — один SELECT), игр в хостинге (`games_list.length`).
3. **Дуо-блок**: закреплённая (или последняя) новость — большая карточка `.feat` со штрихованным градиентным фоном, тегом `◈ ЗАКРЕПЛЕНО`, кликом открывается модалка (перенести текущий безопасный механизм: `data-*` + `encodeURIComponent`, вывод `textContent`); справа панель `LIVE-СЕРВЕРЫ` — строки `.srv-row` с 3px цветной полосой слева (зелёная/красная), имя + игра mono-капсом, игроки, `● ONLINE/OFFLINE`.
4. **Игры в хостинге** `.games`: чипы из `games_list` (настройка уже есть: name+icon). Код игры в квадратике: если у записи есть icon — `<img>`, иначе первые 2–3 буквы. Заголовок секции со счётчиком `NN TITLES`.
5. **Чат + Мониторинг**: панель чата (3 последних сообщения из БД, аватар-квадрат с инициалами mono) + панель `МОНИТОРИНГ · <node>`: CPU/RAM/DISK метры. Данные — fetch `/monitoring/resources` при загрузке (если публично/админ; агрегировать по первому узлу или сумме гостей; при недоступности — скрыть панель и растянуть чат). Футер панели: `NODE <имя> · PROXMOX` + «ДАШБОРД →».

### Фаза 4 — внутренние страницы
1. `/news` (`views/news.ejs`): лента `.news-it` (штрихованная миниатюра 170px слева; если у новости есть `image` — она фоном), мета mono-капсом, закреплённые сверху с `◈`. Модалка чтения.
2. `views/servers.ejs`: карточки `.srv-card` — шапка с кодом игры в квадрате + `● ONLINE`, тело: адрес + кнопка `COPY` (уважать `show_ip_address`), прогресс игроков (`show_player_count`), футер: пинг + «ДЕТАЛИ»/«ЗАПУСТИТЬ» (redirect_enabled). `views/server-detail.ejs` — в том же стиле.
3. `views/community.ejs`: разметка `.chat-line` (аватар-квадрат с 2 буквами ника, ник mono-капсом, время `· HH:MM`); системные тексты акцентом НЕ вводить (нет такой сущности). Socket-логику не менять — только классы и генерацию DOM в JS (`textContent`!). Панель «Онлайн» справа.
4. `views/monitoring/dashboard.ejs`: панели по гостям с метрами CPU/RAM (+DISK если есть данные), заголовок панели: имя + `LXC/VM · up Xd`. Поллинг сохранить.
5. Auth/register/profile/setup/404/500: центрированные панели `.panel`, mono-заголовки, кнопки `.btn-a`/`.btn-o`. CSRF-поля не потерять.

### Фаза 5 — админка
Минимум: работоспособность. Рекомендуется (быстро даёт целостность): перекрасить `admin-nav` в mono-капс с рамочным активным пунктом и таблицы в `.panel`-стиль.
