# План реализации — Концепт A «Командный центр»

> **Эталон**: `demo.html` в этой папке. Перед началом открой его и изучи разметку/CSS — итоговый сайт должен выглядеть так же (с поправкой на реальные данные и шрифты из прода).
> **Обязательно**: прочитай `docs/redesign/README.md` — там общие сведения о проекте и раздел «Инварианты».

## Идея

Сайт превращается в **игровой лаунчер / ops-консоль** (референсы: Steam, Discord). Вместо верхнего навбара — **боковая панель** с разделами и счётчиками. Каждый раздел — отдельный «экран». Главная `/` становится экраном **«Обзор»**: тикер, 4 KPI-плитки и мини-виджеты всех разделов со ссылками «→». Эстетика HUD: фоновая сетка, панели с уголками-скобками, моноширинные метрики, неон циан + фиолет, малые радиусы (8px).

## Дизайн-токены

Взять из `demo.html` (блок `:root`). Ключевые:

| Токен | Тёмная | Светлая |

| `--ok` / `--bad` / `--warn` | `#2be08a` / `#ff5d6b` / `#ffb347` | см. demo |

**Шрифты (Google Fonts, уже разрешены CSP)**: заголовки — `Exo 2` (800), текст — `Inter`, **все метрики/метки/адреса — моноширинный** (добавить `IBM Plex Mono` в подключение Google Fonts, вес 400/600/700). Мono-метки: uppercase, `letter-spacing: .12–.2em`, 10–12px.

**Интеграция с 6 темами**: новые компоненты используют алиасы. В `style.css` добавить мост:
```css
:root[data-theme] {
  --panel: var(--surface);
  --line: var(--border);
  --cyan: var(--primary);
  --violet: var(--accent);
  /* ...и т.д. — полный маппинг по табл. выше */
}
```
Существующие 6 файлов тем продолжают работать; при желании подкрутить их значения под новую эстетику (не обязательно в первой итерации).

## Фазы

### Фаза 1 — токены и мост тем
1. В `style.css`: новые токены + маппинг на переменные тем (см. выше), фоновая сетка `body::before` (см. demo, класс не нужен — глобально), обновлённые примитивы: `.panel`, `.badge`, кнопка `.btn-c`, метры.
2. Подключить `IBM Plex Mono` в `header.ejs` (добавить в существующий Google Fonts URL).

### Фаза 2 — каркас: сайдбар + тикер
1. `views/partials/header.ejs`: заменить `<nav class="navbar">` на грид `.shell` → `<aside class="side">` + `<main class="screen">`. Открывающиеся теги закрывает `footer.ejs` — синхронизировать!
2. Сайдбар: логотип (`⚡ NEXUSHUB` / подпись `game ops console`), пункты с иконками Lucide и счётчиками (серверы `X/Y` — есть в `res.locals`? нет → добавить в глобальный middleware server.js выборку счётчиков через `db.getCachedSettings`-подобный кэш ЛИБО рендерить без счётчиков в первой итерации), карточка пользователя внизу (`user` уже в `res.locals`).
3. Активный пункт: по `req.path` — передать `currentPath` в locals (в server.js middleware: `res.locals.currentPath = req.path`) и сравнивать в шаблоне.
4. Тикер: полоса под верхом экрана; данные рендерятся сервером (кол-во серверов онлайн, игроки — из БД) + время обновляется JS. Без бегущей строки — статичная строка с разделителями (см. demo `.ticker`).
5. Селекторы темы и языка перенести в сайдбар (низ) или тикер — сохранить `id="themeSwitcher"` и `id="languageSelector"`, чтобы `main.js` продолжил работать.
6. Мобильная версия: сайдбар схлопывается в верхнюю панель (см. media query в demo); бургер из `main.js` (`initMobileNav`) адаптировать под новую разметку.

### Фаза 3 — экран «Обзор» (главная)
1. `routes/home.js`: добавить выборки (серверы, 3 сообщения чата, счётчики) — только SELECT.
2. `views/home.ejs`: полностью переверстать по `demo.html` секция `#v-overview`: 4 KPI-плитки (`.stat`), сетка 2 колонки: панель «Серверы» (мини-строки `.mini-srv`), «Чат», «Новости» (3 последних, клик → `/news`), «Инфраструктура» (если `monitoringPublic` или админ — маленькие CPU-метры; данные тянуть fetch'ем с `/monitoring/resources`, при ошибке — скрыть панель).
3. Hero/glitch/games_list с главной убираются (games_list можно вывести компактной строкой в «Обзоре» или на `/servers` — на усмотрение, согласовать).

### Фаза 4 — внутренние экраны
1. `/news` (новый view): лента `.news-item` (миниатюра слева, контент справа), модалка чтения — перенести текущий безопасный механизм из `home.ejs` (данные в `data-*` через `encodeURIComponent`, вывод через `textContent`).
2. `views/servers.ejs`: карточки `.srv-card` из demo (адрес+copy, прогресс игроков, пинг). Уважать `show_ip_address`/`show_player_count`.
3. `views/community.ejs`: перенести разметку панелей из demo (`#v-chat`), **не трогая** socket-логику — только классы/структура DOM (аккуратно: JS создаёт сообщения — обновить генерацию DOM под новые классы).
4. `views/monitoring/dashboard.ejs`: карточки `.mon-*` из demo; существующий поллинг `/monitoring/resources` сохранить, поменять только рендер карточек.
5. Формы auth (login/register/profile), setup, ошибки 404/500 — перекрасить в токены (панели, кнопки), без структурных изменений.
